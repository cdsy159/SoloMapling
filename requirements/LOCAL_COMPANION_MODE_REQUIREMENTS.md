# 冒险岛 v83 本地单机队友模式需求说明

本文档面向 MapleStory v83 服务端，也就是本项目基于 Cosmic 运行的 GMS v83 冒险岛服务端。所有队友需求都必须遵守冒险岛原版的队伍、职业、技能、装备、地图移动、Boss 远征、掉落和经验规则。

## 1. 项目目标

将 SoloMapling 从“大量环境机器人模拟”改造成“冒险岛 v83 本地单机队友系统”。

目标形态：

- 一个真人玩家使用正常 MapleStory v83 客户端游玩。
- 服务端按需生成少量 Artificial Players，作为玩家的固定队友。
- 队友会以冒险岛真实队伍成员的身份组队、跨地图跟随、攻击普通怪物和 Boss。
- 队友有自己的等级、职业、技能、背包、装备、消耗品成长状态。
- 玩家可以控制队友的战斗方式、掉落分配、背包和装备。
- 游戏重启后，队友的成长状态仍然保留。

该模式不以公网多人运营为目标，不需要保留大型服务器的人口模拟、经济模拟、防作弊和反自动脚本需求。

## 1.1 冒险岛 v83 前提

需求中的术语必须按 MapleStory v83 的实际游戏机制理解。

| 本文术语 | 冒险岛 v83 对应机制 |
|---|---|
| 队友 | 服务端中的真实 `Character`，加入玩家的 MapleStory Party |
| 队伍 | 冒险岛原生 Party，最多 6 人，玩家必须担任队长 |
| 职业 | 冒险家、骑士团等 v83 职业及其一转、二转、三转、四转路线 |
| 成长 | 等级、EXP、AP、SP、技能等级和转职 |
| 背包 | EQUIP、USE、SETUP、ETC、CASH 五类库存 |
| 装备 | 装备栏、武器、防具、饰品、现金装备和卷轴强化状态 |
| 恢复 | 红色药水、蓝色药水、食物、治疗技能和牧师系恢复能力 |
| 弹药 | 弓箭、弩箭、飞镖、子弹等消耗品 |
| 队伍增益 | Bless、Haste、Hyper Body、Holy Symbol、Maple Warrior 等 |
| 复活 | Bishop 的 Resurrection，以及冒险岛角色死亡后的复活流程 |
| Boss | 野外 Boss 和通过 Expedition/远征系统进入的 Boss |
| 掉落 | 冒险岛物品归属保护、队伍掉落、Boss 掉落和任务物品 |
| 地图移动 | 传送门、绳索、梯子、跳台、飞船、出租车和特定剧情传送 |

不应引入不属于 v83 的系统，例如 Star Force、Arcane Symbol、5 转、现代潜能系统等。装备成长应围绕 v83 的卷轴、强化次数、Boss 装备和等级要求设计。

## 3. 当前主要限制

### 3.1 跟随和战斗是分开的

`FollowerBot` 可以跨地图跟随玩家，但主要职责是移动。

`TrainingBot` 会攻击怪物，并会优先前往真人队友所在的可刷怪地图，但它不会持续贴着玩家移动。

目标模式需要一个新状态机，同时负责：

- 跟随玩家。
- 锁定并攻击附近怪物。
- 保持合理队形。
- 切换地图后重新加入战斗。
- 玩家停下、上跳、钻传送门时正确处理。

### 3.2 机器人目前偏“演出”，不是完整生存系统

机器人承受接触伤害和掉落伤害时，目前主要是播放受伤和击退效果，不真正扣除 HP，也不会死亡。

冒险岛 v83 的队友要参与 Boss 和长期成长，必须增加：

- 真实 HP、MP。
- 按冒险岛职业公式计算物理防御、魔法防御和减伤。
- 红药、蓝药、食物和百分比恢复药水的自动使用。
- 死亡、返回城镇、Safety Charm 和 Bishop Resurrection 等复活流程。
- 中毒、封印、黑暗、虚弱、昏迷、反向等异常状态和 Dispel。
- 复活技能、复活药水和队友复活。

### 3.3 机器人伤害是调优模型，不是装备属性模型

当前机器人攻击伤害主要由职业和等级档位决定，不是完整地读取角色力量、敏捷、智力、运气、武器攻击力和技能加成。

在冒险岛 v83 中，要让“打装备和提升”成立，伤害必须改为：

```text
机器人真实属性
  + 技能等级
  + 武器和装备属性
  + 增益效果
  + 怪物防御
  = 最终伤害
```

否则换装备不会真正提升输出。

物理职业需要读取 STR/DEX、武器攻击力和熟练度，魔法职业需要读取 INT/LUK、魔法攻击力和技能倍率，弓箭手、飞侠和海盗还要处理武器类型、弹药和攻击段数。

### 3.4 机器人状态默认不持久化

当前机器人通常从基础角色临时复制，装备和背包变化主要保存在内存中。Cosmic 的角色自动存档会跳过机器人，因此这些角色不符合冒险岛长期培养需求。

本地单机队友需要持久化以下内容：

- 角色等级、经验、职业。
- HP、MP、AP、SP。
- 已学习技能和技能等级。
- 背包、装备和金币。
- 外观、发型、脸型。
- 当前行为配置和队伍关系。
- 掉落分配策略。

## 4. 功能需求

### 4.1 队友生命周期

必须支持：

- 创建 1 到 5 个队友，使玩家与队友组成最多 6 人的冒险岛队伍。
- 指定角色名、职业分支、性别、脸型、发型和初始外观。
- 在玩家附近召唤队友。
- 将队友收回或退出世界。
- 解散队友并将队友从数据库删除。
- 查看所有队友的基本状态。
- 设置队友为当前主队伍成员。
- 支持冒险家职业树和骑士团职业树。
- 支持一转、二转、三转和四转所需的职业状态。

建议默认值：

- 最大队友数：3。
- 队伍总人数上限：4，包括玩家本人；预留扩展到冒险岛最大 6 人队伍。
- 队友不允许被其他普通玩家招募。
- 队友不会因为地图空闲、交易结束或随机概率自动转换类型。

### 4.2 队伍关系

必须支持：

- 玩家是固定 Party Leader。
- 队友自动接受玩家的组队邀请。
- 队友拒绝其他人的组队邀请。
- 玩家登录后自动恢复队友队伍。
- 队友掉线或地图不同步后自动重新加入。
- 玩家切换频道时必须处理队友所在频道。
- 队伍 UI 中正常显示队友的职业、等级、HP 和地图状态。
- 进入远征时，队友可以随玩家加入 Expedition。

当前实现主要集中在单一世界和频道。如果玩家可能切换频道，需要补充跨频道队友管理。

本地单机模式建议固定使用一个世界。若玩家切换频道，队友应自动切换到同一频道，不能继续停留在旧频道并假装仍在队伍中。

### 4.3 行为模式

每个队友至少需要以下模式：

| 模式 | 行为 |
|---|---|
| 跟随 | 跟着玩家，不主动攻击 |
| 跟随战斗 | 跟着玩家，并攻击附近怪物 |
| 定点战斗 | 留在当前地图指定区域刷怪 |
| 被动 | 不移动、不攻击，只响应交易和操作 |
| 停留 | 留在当前位置，等待玩家回来 |

行为切换必须即时生效，并且不能被旧的移动任务覆盖。

还需要支持：

- 统一设置整队模式。
- 单独设置某个队友模式。
- 查看当前模式。
- 防止模式切换过程中出现两个移动控制器同时操作机器人。

### 4.4 跟随战斗

核心要求：

- 与玩家保持可配置距离。
- 与玩家保持在同一平台或附近平台。
- 玩家换地图时跨地图跟随。
- 玩家使用传送门时正确跟进。
- 正确处理绳索、梯子、跳跃平台、掉落平台和地图边界。
- 对飞船、出租车、剧情传送等特殊移动提供跟随或受控传送方案。
- 玩家进入 Boss 地图时全部队友跟进。
- 队友掉队后优先追赶玩家，而不是继续追怪。
- 玩家死亡后停止战斗并返回玩家位置。
- 玩家离开地图后停止刷怪并重新跟随。

战斗目标规则：

- 优先攻击玩家正在攻击的目标。
- 没有当前目标时攻击最近的敌对怪物。
- Boss 地图优先攻击 Boss。
- 可配置是否攻击普通怪物。
- 可配置攻击距离和放弃追击距离。
- 怪物距离玩家过远时停止追击。

建议增加队伍站位：

- 近战队友位于玩家前方。
- 远程和法师队友位于玩家后方。
- 治疗职业保持最远距离。
- 多个队友不能堆叠在同一个坐标。

### 4.5 职业职责

为了让组队有实际意义，需要区分队友职责。

| 职责 | 行为 |
|---|---|
| 坦克 | 吸引仇恨，靠近 Boss，承受更多攻击 |
| 输出 | 优先攻击当前目标，使用职业技能循环 |
| 远程输出 | 保持距离，优先安全位置 |
| 治疗 | 根据 HP 阈值治疗玩家和队友 |
| 辅助 | 自动施放 Holy Symbol、Maple Warrior、Bless 等队伍增益 |
| 复活 | 自动复活死亡队友，或等待玩家确认 |

至少需要支持以下队伍增益：

- Bless：提升队伍攻击、防御、命中和回避。
- Haste：提升移动速度和跳跃力。
- Hyper Body：提升队伍最大 HP 和 MP。
- Holy Symbol：提升队伍经验和掉落收益。
- Maple Warrior：按比例提升队伍主属性。
- 治疗和 Dispel：恢复队伍 HP 并解除异常状态。
- Resurrection：复活死亡队友。

### 4.6 技能、MP 和消耗品

必须支持：

- 冒险岛职业技能等级真实读取。
- SP 分配和技能等级对应关系。
- 技能 MP 消耗。
- 技能冷却和吟唱时间。
- 施法距离和怪物数量限制。
- 四转技能书、技能精通等级和 Master Level 规则。
- 机器人 MP 不足时使用蓝色药水或停止施法。
- 机器人 HP 低于阈值时使用红色药水或食物。
- 药水和弹药不足时提醒玩家。
- 可配置自动回城补货。
- 可配置药品保留数量。
- 弓箭手消耗箭矢和弩箭。
- 飞侠消耗可充能的飞镖。
- 枪手消耗子弹并在必要时回城充值。

如果队友拥有治疗能力，需要根据整队 HP 选择治疗时机，不能只治疗自己。

### 4.7 Boss 战

冒险岛 v83 的 Boss 战需要比普通刷怪更严格的 AI。仓库当前已经包含 Balrog、Scarga、Showa、Zakum、Horntail、Chaos Zakum、Chaos Horntail、Pink Bean、CWKPQ 和 Ariant 等 Expedition 类型，也存在 Papulatus 等 Boss 日志逻辑。

建议支持顺序：

1. Balrog Easy、Balrog Normal、Zakum、Papulatus。
2. Scarga、Showa、Horntail。
3. Chaos Zakum、Chaos Horntail、Pink Bean、CWKPQ。

必须支持：

- 进入 Boss 地图前检查人数和等级。
- 正确处理 Expedition 注册、远征队长和 6 人上限。
- 支持 `USE_ENABLE_SOLO_EXPEDITIONS`，允许本地玩家与队友组成不足原版最低人数的远征队。
- 正确处理 Boss 前置任务、火眼和进入地图所需物品。
- Boss 地图内禁止队友随意离开跟随范围。
- 锁定 Boss 本体和 Boss 部位。
- 识别 Boss 阶段和无敌状态。
- 避免持续攻击无敌目标。
- 对高伤害技能进行躲避或保持距离。
- Boss 死亡后停止攻击并回到玩家身边。

建议支持：

- Boss 仇恨集中于坦克队友。
- 治疗职业优先保证玩家存活。
- 队员死亡后在安全位置自动复活。
- Boss 地图清空后统一传送回城。
- 记录 Boss 击杀和掉落。

Boss 战初期不需要实现所有特殊机制，但第一批必须覆盖冒险岛常见的 Zakum、Balrog 和 Papulatus，并确保队友能够正确参加 Expedition、攻击 Boss 部位、复活和领取掉落。

### 4.8 经验与成长

必须使用冒险岛 v83 正常的队伍经验分配逻辑，而不是只增加装饰性等级。Cosmic 已经实现同地图队伍经验、伤害贡献、队伍等级差和 Leech 区间，队友应该直接复用这些规则。

需要支持：

- 玩家和队友共同获得怪物经验。
- 队友必须与怪物和其他贡献队伍成员处于允许的等级差范围内，才能正常获得经验。
- Boss 战按照玩家和队友的实际伤害贡献参与经验分配。
- 队友等级提升。
- 队友获得 AP 和 SP。
- AP 按职业自动分配。
- SP 按配置自动学习技能。
- 达到等级后完成一转、二转、三转和四转。
- 处理四转技能书和 Master Level。
- 技能升级后实际提升伤害、治疗或增益。
- 等级不足时不能挑战对应 Boss。
- 队友升级时正常广播升级特效、属性更新和技能更新。

建议增加成长策略：

- 自动分配 AP。
- 自动学习职业技能。
- 自动执行职业转职，或要求玩家确认。
- 自动保留部分 SP。
- 手动重新分配 AP 和 SP。

### 4.9 掉落与物品分配

冒险岛 v83 使用金币、物品、装备、任务物品和 Boss 掉落分离的掉落流程。物品通常存在约 15 秒归属保护期，随后变成自由拾取；组队时还会涉及队伍所有权。本地队友模式必须有明确的掉落归属策略，不能依赖现有的环境机器人随机拾取。

| 模式 | 规则 |
|---|---|
| 全部给玩家 | 队友不拾取，玩家拾取全部物品 |
| 全部给队友 | 队友拾取，玩家可以通过背包界面取回 |
| 轮换分配 | 装备和稀有物品在玩家与队友之间轮换 |
| 职业优先 | 装备优先分配给可使用该装备的队友 |
| 只捡指定物品 | 只拾取白名单物品 |
| 不拾取 | 所有掉落保留在地面 |

还需要支持：

- 金币分配。
- 普通物品分配。
- 装备分配。
- 任务物品处理。
- Boss 专属掉落处理。
- 背包满时停止拾取并通知玩家。
- 防止同一物品被玩家和队友重复拾取。
- 防止交易和拾取同时修改同一个物品导致复制。

建议默认：

- 金币平均进入玩家和队友账户。
- 装备先进入玩家背包。
- 消耗品按队友职业自动分配。
- 任务物品只由玩家拾取。
- 未过期且属于玩家的掉落不能被队友抢走。
- Boss 装备和稀有卷轴默认归玩家。
- 药水、箭矢、飞镖和子弹可以按需补充给队友。

### 4.10 背包和装备管理

玩家必须能够通过冒险岛原生交易窗口或自定义队友管理菜单来管理队友装备。v83 的装备栏包括帽子、脸饰、眼饰、耳环、上衣、裤裙、套服、鞋子、手套、披风、盾牌、武器、戒指和现金装备槽位。

最低要求：

- 查看队友背包。
- 与队友交易物品。
- 把装备从玩家背包移动给队友。
- 让队友穿戴指定装备。
- 让队友卸下装备。
- 查看装备前后属性变化。
- 防止队友自动出售或丢弃锁定物品。

完整要求：

- 独立队友背包界面。
- 装备属性对比。
- 装备职业、等级、性别和武器类型要求检查。
- 使用卷轴强化，并正确处理成功率和升级次数。
- 支持 10%、60%、100%、混沌卷、白衣卷和黄金锤等 v83 强化内容。
- 装备升级次数、可升级状态和不可交易状态显示。
- 装备修复。
- 物品锁定。
- 一键整理。
- 一键换装方案。
- 保存每个队友的装备套装。
- 处理现金装备和普通装备的外观分离。

如果不想修改客户端 UI，可以先通过原生交易窗口和聊天命令实现，后续再增加 NPC 菜单。

### 4.11 装备影响

装备必须真正影响冒险岛 v83 的角色数据：

- 武器攻击力影响伤害。
- 魔法攻击力影响法师伤害。
- 防御力影响受到的伤害。
- 属性加成影响最大 HP、MP 和输出。
- 命中率和回避率影响 Boss 和高级怪物战斗。
- 移动速度影响跟随。
- 跳跃力影响复杂地图寻路。
- 武器熟练度影响伤害下限。
- 增益技能和装备效果正确叠加。

换装后必须立即：

- 更新角色属性。
- 更新角色外观。
- 广播外观变化。
- 更新战斗模型。
- 保存到数据库。

装备模型必须限制在 v83 范围内，不引入 Star Force、潜能、附加潜能、Arcane Symbol 和现代装备系统。

### 4.12 死亡与复活

必须支持：

- 队友 HP 归零后进入死亡状态。
- 死亡后停止移动、攻击和拾取。
- 队友死亡后按照 v83 规则返回最近城镇或停留在死亡地图，由配置决定。
- 玩家可以手动复活队友。
- Bishop 四转的 Resurrection 可以复活玩家和阵亡队友。
- 支持 Safety Charm 和复活消耗品。
- Boss 战后统一复活。
- 复活后恢复 HP、MP 和地图位置。
- 复活的队友需要重新获得队伍增益。
- 可配置死亡是否损失经验。

建议单机模式默认：

- 队友死亡不损失经验。
- 玩家死亡后队友停止战斗并等待。
- 玩家使用 Safety Charm 或 Bishop 复活后，队友重新进入战斗。
- Boss 团灭后整队返回最近城镇。

### 4.13 持久化和恢复

这是本地单机模式最重要的新增模块之一。

必须保存：

- 队友角色基本数据。
- 属性、等级、经验、AP、SP。
- 技能和技能等级。
- 装备、背包、金币和消耗品。
- 世界、频道、地图和坐标。
- 队长关系。
- 当前行为模式。
- 掉落策略。
- 装备方案和自动补给配置。

必须支持：

- 定时自动保存。
- 切换地图时保存。
- 交易完成后保存。
- 装备变化后保存。
- 正常关闭服务端时保存全部队友。
- 异常退出后的恢复。
- 手动备份和恢复。

建议将队友作为真实数据库角色保存，但不要出现在普通角色选择列表中。也可以新增独立的 `companions` 表和存档结构，避免和普通玩家角色管理混在一起。

### 4.14 玩家操作入口

最低可用方案使用聊天命令：

```text
@companion spawn <职业>
@companion summon
@companion dismiss
@companion follow
@companion attack
@companion passive
@companion stay
@companion status
@companion loot <模式>
@companion trade <队友>
@companion inventory <队友>
@companion equip <队友> <背包槽位>
@companion unequip <队友> <装备槽位>
@companion save
```

建议增加统一菜单：

- 选择队友。
- 设置行为模式。
- 查看 HP、MP、等级和经验。
- 查看当前目标。
- 查看背包剩余空间。
- 查看药水和弹药。
- 设置掉落策略。
- 执行装备和交易操作。

## 5. 稳定性与安全要求

必须避免：

- 玩家和队友同时拾取同一种物品。
- 交易确认期间物品被另一个操作移除。
- 队友地图切换和装备操作并发执行。
- 死亡、交易、传送同时发生导致状态卡死。
- 服务端崩溃导致背包或装备丢失。
- 重复生成同一队友。
- 队友被环境人口系统再次随机招募或转换。
- 队友进入必须由真人脚本控制的剧情地图。

需要增加：

- 队友操作锁。
- 物品移动事务。
- 统一的移动控制器。
- 存档失败重试。
- 队友异常自动恢复。
- 诊断命令。

## 7. 推荐实现结构

建议不要直接把所有逻辑塞进 `FollowerBot`，而是新增独立的 `CompanionBot`。

```text
CompanionManager
  - 队友创建、加载、保存和删除

CompanionBot extends BotSM
  - 当前行为模式
  - 队伍关系
  - 状态机

CompanionMovementController
  - 跟随、追赶、站位、Boss 地图移动

CompanionCombatController
  - 目标选择、技能循环、Boss 优先级

CompanionSupportController
  - 药水、治疗、复活、队伍增益

CompanionExpeditionController
  - Expedition 注册、Boss 地图、Boss 部位和团灭恢复

CompanionInventoryService
  - 背包、装备、交易和物品事务

CompanionPersistenceService
  - 数据库存档和恢复

CompanionCommandHandler
  - 玩家命令和菜单
```

推荐让 `CompanionBot` 复用以下现有组件：

- `GCMovement`：移动和寻路。
- `BotAttackDriver`：攻击动作和怪物选择。
- `BotPartyCommands`：冒险岛 Party 操作。
- `BotTradeCommands`：冒险岛交易窗口。
- Cosmic 原生职业、技能、怪物、背包、经验、掉落和数据库系统。
- Cosmic 原生 Expedition 和 Boss Log 系统。

`LOCAL_COMPANION_MODE` 开启时，应关闭 Free Market 人口、社会机器人、Blackjack、Drop Game、JQ、OPQ 和自动 Training Bot 人口等环境功能。保留 `BotClient`、`BotSM`、移动和攻击基础设施即可。

## 8. 实施阶段

### 阶段 0：清理环境

- 关闭自动世界机器人。
- 只保留按需生成。
- 增加最小队友生成命令。

### 阶段 1：可玩 MVP

- 生成 1 到 3 个冒险岛职业的队友。
- 创建冒险岛 Party。
- 通过传送门、绳索、梯子和平台跨地图跟随。
- 跟随状态攻击普通怪物。
- 使用真实 HP、MP、红药和蓝药。
- 基础受伤、死亡、Safety Charm 和 Bishop 复活。
- 掉落全部归玩家。

达到这一阶段后，已经可以进行普通地图组队刷怪。

### 阶段 2：成长与持久化

- 队友保存到数据库。
- 正常获得经验和升级。
- AP、SP 和技能系统。
- 玩家装备影响伤害和防御。
- 交易、背包和换装。
- 多套装备方案。
- 掉落分配模式。

达到这一阶段后，队友可以长期培养。

### 阶段 3：Boss 支持

- 支持 Balrog Easy/Normal、Zakum 和 Papulatus。
- 支持 Expedition 注册和单人远征配置。
- Boss 本体、Zakum 手臂和其他多部位目标。
- 仇恨、治疗、Holy Symbol、Hyper Body 和 Maple Warrior。
- Boss 地图跟随、平台站位和撤退。
- Boss 掉落、Boss 装备和任务物品分配。
- 死亡、Safety Charm 和 Bishop Resurrection。
- 在基础能力稳定后扩展到 Horntail、Chaos 版本、Pink Bean 和 CWKPQ。

达到这一阶段后，可以稳定组队挑战常用远征 Boss。

### 阶段 4：体验完善

- NPC 队友管理菜单。
- 队友 HUD。
- 自动补给。
- 装备方案切换。
- 存档恢复和备份。
- 战斗平衡和异常恢复。

## 9. 验收标准

一个可接受的本地单机队友版本至少应满足：

- 服务端启动后默认只有玩家和指定队友，没有大量随机机器人。
- 玩家可以在不输入 GM 参数的情况下召唤和管理队友。
- 玩家和队友组成符合冒险岛规则的 Party，并正确显示队伍 UI。
- 队友可以稳定跨地图跟随，并处理传送门、绳索、梯子和跳跃平台。
- 队友可以攻击普通怪物和 Boss，并受到真实 HP 伤害。
- 队友会使用红药、蓝药、技能、队伍增益和复活能力。
- 玩家可以交易、查看背包并更换队友装备。
- 换装、卷轴强化后属性、外观和实际伤害都发生变化。
- 队友会按冒险岛队伍经验规则获得经验、升级、获得 SP 并学习技能。
- 玩家和队友可以通过 Expedition 完成至少 Zakum、Balrog 和 Papulatus。
- Boss 掉落不会丢失或复制。
- 服务端重启后队友成长、背包和装备不丢失。
- 队友异常不会导致服务端崩溃或卡在无法恢复的状态。

## 10. 需要提前决定的问题

实施前建议确定：

1. 队友最大数量是 1、3 还是 5；冒险岛 Party 本身最多 6 人。
2. 队友是否需要从 1 级开始培养。
3. 是否允许玩家创建任意冒险家或骑士团职业队友。
4. 是否必须修改客户端 UI，还是聊天命令和 NPC 菜单即可。
5. 队友是否使用真实角色数据库记录。
6. 队友死亡是否损失经验。
7. Boss 是否沿用原版每日次数限制。
8. 掉落默认归玩家还是轮换分配。
9. 是否允许自动补给到仓库取药。
10. 是否需要队友自动加点和自动学习技能。

建议默认方案：

- 3 个队友。
- 从可配置等级开始，而不是全部从 1 级开始。
- 支持所有常规冒险家职业，骑士团职业作为后续扩展。
- 先做聊天命令和 NPC 菜单，不做客户端修改。
- 使用独立持久化数据。
- 队友死亡不扣经验。
- Boss 每日限制可配置。
- 装备和稀有 Boss 掉落默认归玩家。
- 优先支持 Balrog、Zakum 和 Papulatus。

## 11. 难度评估

| 模块 | 难度 | 主要原因 |
|---|---|---|
| 关闭大量机器人 | 低 | 已有启动开关 |
| 少量队友生成 | 低 | 已有 `BotGeneration` |
| 自动组队 | 低 | 已有队伍系统 |
| 跨地图跟随 | 低到中 | 已有 `FollowerBot` 和 `GCMovement` |
| 绳索、梯子和复杂平台跟随 | 中 | 冒险岛地图移动形式较多 |
| 跟随并攻击 | 中 | 需要移动、目标选择和战斗统一 |
| HP、MP、死亡和复活 | 中 | 当前机器人主要是演出，不是真实生存 |
| v83 属性伤害模型 | 中到高 | 需要接入装备、技能、熟练度和防御公式 |
| 职业转职、AP、SP 和技能书 | 中 | 需要复用角色成长系统 |
| 背包、换装和卷轴 | 中 | 有数据结构，但玩家操作入口需要新增 |
| 持久化和恢复 | 中到高 | 当前机器人默认不存档 |
| Expedition 和普通 Boss | 中到高 | 需要注册、人数、地图、仇恨、治疗和掉落处理 |
| 高级 Boss 机制 | 高 | Zakum 部位、Horntail、Pink Bean 和 CWKPQ 差异很大 |
| 完整游戏内 UI | 高 | 可能需要客户端协议或大量 NPC 菜单 |

粗略工作量估计，前提是开发者熟悉 Java 和该项目：

- 可玩 MVP：1 到 2 周。
- 带持久化、成长、装备和普通 Boss 的可用版本：3 到 6 周。
- 包含完整 UI、Boss 机制和稳定恢复的完善版本：6 到 10 周以上。

最终结论：这个目标不是在现有仓库上简单打开几个开关，但也不需要重写冒险岛服务端。最合理的方向是保留 Cosmic 和现有机器人基础设施，新建一个面向 MapleStory v83 本地单机玩家的 `Companion` 层，把现有移动、战斗、Party、Expedition、交易和存档能力重新组合。
