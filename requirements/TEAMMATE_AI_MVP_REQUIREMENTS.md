# SoloMapling 队友 AI MVP 需求文档

版本：0.1

状态：初步实现范围

## 1. 背景

SoloMapling 当前以大规模环境机器人和独立机器人状态机为主，已经具备寻路、普通刷怪、拾取、组队、交易和部分组队任务能力，但还不是一个完整的长期队友系统。

本阶段目标不是在游戏客户端内增加新 UI，而是：

1. 使用 SoloMapling 作为服务端。
2. 使用现有 Cosmic-client 作为游戏客户端，不修改 EXE 和 WZ 资源。
3. 将少量 AI 角色作为真实队友加入玩家队伍。
4. 使用独立的第三方 Web 或桌面工具查看队友状态并执行管理操作。
5. 先覆盖跨地图跟随、普通刷怪、自动补给、自动拾取、月妙类机制副本、常见 Boss 和队友管理。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 玩家 | 使用正常 MapleStory v83 客户端登录的唯一真人角色 |
| AI 队友 | 服务端中的真实 `Character`，加入玩家的 MapleStory Party |
| 队长 | 当前真人玩家，固定作为队友的跟随和任务目标 |
| 外部工具 | 通过 SoloMapling 管理 API 显示状态和执行操作的 Web 或桌面应用 |
| 普通地图 | 不依赖副本地图实例的野外地图 |
| 副本实例 | 使用 `EventInstanceManager` 或等价系统创建的地图实例 |
| Boss 档案 | 描述某个 Boss 的目标、阶段、危险机制、走位和补给规则的配置 |

## 3. MVP 范围

本阶段只实现以下五组能力：

1. 队友跨地图跟随玩家。
2. 队友死亡后自动复活，并重新寻路到玩家所在地图。
3. 队友自动寻找怪物、攻击、吃恢复药和拾取掉落。
4. 队友能够完成月妙类机制副本和常见 Boss。
5. 外部工具能够读取队友状态并执行交易、AP/SP 分配、技能和装备操作。

本阶段不实现：

- 游戏客户端内的队友背包或控制面板。
- 所有职业的完整最优技能循环。
- 所有冒险岛组队任务。
- 所有 Boss 的逐帧机制模拟。
- 公网多人和商业化运营所需的完整安全体系。
- AI 队友之间的复杂社交和长期经济行为。

## 4. 约束与前提

### 4.1 客户端约束

- 继续使用 Cosmic-client，不增加客户端封包和 UI。
- 队友的 HP、MP、装备和外观变化必须通过标准 v83 封包同步给游戏客户端。
- 外部工具不在游戏画面内显示，使用浏览器或独立桌面窗口。

### 4.2 服务端约束

- 所有状态修改必须通过 SoloMapling 服务层执行，不允许外部工具直接修改数据库。
- 所有战斗、装备、掉落、任务和交易行为必须由服务端权威校验。
- 同一名 AI 队友同一时间只能运行一个主状态机。
- 外部工具操作和 AI 自主行为发生竞争时，人工操作优先，并暂停相关 AI 状态。

### 4.3 战斗真实度

为了让 AP、SP、技能和装备真正影响战斗，AI 队友的伤害和生存必须逐步改为读取真实角色数据：

```text
角色属性
  + 技能等级和技能倍率
  + 装备属性
  + Buff 效果
  + 怪物防御和抗性
  = 最终伤害
```

MVP 可以保留现有伤害公式作为兼容回退，但使用真实装备后必须能够体现输出差异。

## 5. 功能需求

### FR-1 跨地图跟随、死亡和复活

#### FR-1.1 队伍关系

- 玩家是固定队长。
- AI 队友在服务端加入玩家所在的 Party。
- 队友拒绝无关玩家的组队邀请。
- 玩家重新登录后，已有队友能够重新绑定队长。
- 玩家和队友必须保持在相同 World、Channel 和地图实例。

#### FR-1.2 同地图跟随

- 队友同地图内持续跟随队长。
- 跟随距离必须可配置。
- 队长停止时队友停止无意义移动。
- 队长跨越平台时，队友通过跳跃、绳索、梯子和瞬移技能追赶。
- 队友应避免与队长和其他队友严重重叠。
- 队友掉队后优先追赶队长，而不是继续攻击远处的怪物。

#### FR-1.3 跨地图跟随

- 队长进入普通传送门后，队友通过世界地图和寻路图追踪到目标地图。
- 支持脚本传送门、隐藏传送门、定时交通和特殊移动的已知适配。
- 队友进入新地图后从目标地图入口寻路到队长附近。
- 队长切换频道时，队友切换到同一频道，或者明确进入待恢复状态。
- 副本实例中不能只依赖全局地图 ID，必须解析队长所在的 `EventInstance`。

#### FR-1.4 死亡与复活

- 队友使用真实 HP、MP 和死亡状态。
- HP 降到 0 后停止攻击、拾取和主动移动。
- MVP 默认在最近城镇复活。
- 复活后恢复到安全 HP/MP 比例。
- 复活完成后自动寻路到队长所在地图。
- 如果队长位于不可再次进入的副本实例，队友进入待命状态并通知外部工具。
- 支持未来扩展到 Safety Charm、复活技能和队友复活。

#### FR-1.5 跟随战斗

MVP 需要一个统一的 `CompanionBot` 行为，而不是在 `FollowerBot` 和 `TrainingBot` 之间反复转换：

- 未发现怪物时跟随队长。
- 发现怪物时在队长附近自主战斗。
- 怪物距离队长过远时放弃追击。
- 队长换图时立即暂停战斗并开始跟随。
- 进入 Boss 或副本后切换对应行为档案。

### FR-2 自动战斗、补给和拾取

#### FR-2.1 自动战斗

- 自动扫描附近可攻击怪物。
- 没有锁定目标时选择最近、最合适的目标。
- 支持近战、远程和魔法攻击。
- 根据职业和装备选择单体或群体技能。
- 至少支持普通攻击、主攻技能、群体技能和 Buff。
- 技能冷却期间不会重复发送无效攻击。
- 目标不可达时重新选择目标。
- 不攻击友好 NPC、任务护送目标和处于无敌阶段的 Boss。

#### FR-2.2 生存和补给

- HP 低于配置阈值时使用 HP 药。
- MP 低于配置阈值时使用 MP 药。
- 支持固定值和百分比阈值。
- 支持不同地图、Boss 和副本使用不同补给配置。
- 没有可用药水时停止危险战斗并通知外部工具。
- 中毒、封印、黑暗、虚弱和眩晕至少能够识别并执行基础恢复策略。
- 牧师类职业在 MVP 中至少支持自我治疗。

#### FR-2.3 自动拾取

- 自动拾取金币、普通物品、装备和任务物品。
- 支持物品白名单和黑名单。
- 支持按物品类型和稀有度设置拾取规则。
- 不拾取无权限物品。
- 背包满时停止拾取并通知外部工具。
- 需要时能够把拾取结果转移给队长。

#### FR-2.4 队友交易

- 队友能够接受队长的交易请求。
- 队友能够把指定物品或金币提交到交易窗口。
- 队友能够接收队长提供的物品和金币。
- 交易遵循 v83 原生锁定和确认流程。
- 队友断线、死亡或换图时安全取消交易。
- 外部工具触发的交易也必须经过相同的服务端校验。

### FR-3 月妙类机制副本

MVP 以冒险岛 v83 月妙任务作为第一个普通机制副本验收目标。

#### FR-3.1 通用副本能力

- 识别玩家所在的副本实例和当前阶段。
- 与 NPC 对话并选择正确选项。
- 在阶段要求时击杀怪物、拾取物品、提交物品或保护目标。
- 按队长位置和副本状态更换行为。
- 副本失败或队员死亡后能够重试。
- 离开副本后恢复普通跟随战斗。

#### FR-3.2 月妙任务

- 自动跟随队长进入副本。
- 清理会攻击月妙的怪物。
- 自动拾取月妙产生的年糕。
- 按副本脚本要求提交或掉落年糕。
- 保持月妙存活。
- 阶段完成后跟随队长进入下一阶段或离开副本。
- 不因拾取或打怪长期偏离队长导致副本阶段卡死。

#### FR-3.3 跳箱和跳台机制

- 支持记录路线和动态路线两种实现方式。
- 路线失败时允许有限重试。
- 多次失败后通知外部工具，不无限循环。
- MVP 只保证配置过的地图，不承诺自动理解所有跳台地图。

### FR-4 常见 Boss

MVP 使用可配置的 Boss 档案，不为每个 Boss 编写不可复用的一次性代码。

#### FR-4.1 Boss 档案字段

```text
Boss ID
地图和实例要求
阶段判定
主要目标
攻击优先级
必须躲避的技能
安全站位
补给阈值
Buff 顺序
复活和重进策略
失败退出条件
```

#### FR-4.2 通用 Boss 行为

- 进入 Boss 地图后优先锁定 Boss。
- 召唤小怪时根据配置决定集火 Boss 或清理小怪。
- 对反伤、魔法免疫、物理免疫和无敌阶段停止无效攻击。
- HP/MP 阈值比普通地图更保守。
- 死亡后根据 Boss 类型选择复活重进或等待队伍复活。
- Boss 被击杀后停止攻击并跟随队长离开。

#### FR-4.3 MVP Boss 验收

至少选择两类代表性 Boss：

- 多部位、主要站桩输出型 Boss，例如扎昆。
- 带地图或阶段机制型 Boss，例如帕普拉图斯。

具体上线顺序可以在实现阶段调整，但必须通过档案配置支持，不应把行为硬编码到通用攻击循环。

### FR-5 外部管理工具

#### FR-5.1 部署方式

- 管理 API 运行在 SoloMapling 进程内，或者通过受控内部通信连接到 SoloMapling。
- 不通过游戏频道端口发送管理请求。
- 外部工具不直接连接并修改数据库。
- 默认绑定 `localhost` 或私有网络，不直接暴露到公网。

#### FR-5.2 状态读取

外部工具必须能够读取：

- 角色 ID、名称、职业、等级和经验。
- 当前地图、频道、位置、HP、MP 和在线状态。
- AP、已分配属性、剩余 AP。
- SP、技能列表和技能等级。
- 装备栏和装备属性。
- 五种背包的物品、数量、槽位和基本属性。
- 当前 AI 模式、目标、行为状态和错误状态。
- 当前队伍、队长和队友关系。

#### FR-5.3 属性与技能

- 增加或分配 AP。
- 重置或重新分配 AP。
- 分配 SP。
- 学习和提升合法技能。
- 检查职业、等级、前置技能和技能上限。
- 所有修改必须有预览、确认和结果返回。

#### FR-5.4 装备和背包

- 查看装备栏和背包。
- 装备、卸下和替换装备。
- 不同装备预设之间切换。
- 校验职业、等级、属性、槽位和装备限制。
- 修改后重新计算角色属性。
- 使用标准封包让游戏客户端刷新装备和外观。
- 拒绝并发冲突、已移动物品和非法槽位操作。

#### FR-5.5 交易

- 玩家与 AI 队友之间创建交易。
- 双向添加物品和金币。
- 双方锁定和确认。
- 显示交易结果和失败原因。
- 交易中暂停队友的移动、攻击和装备管理。
- 对断线、死亡、换图和超时执行回滚。

#### FR-5.6 API

建议最小接口：

```text
GET  /api/party
GET  /api/teammates/{id}
GET  /api/teammates/{id}/stats
GET  /api/teammates/{id}/skills
GET  /api/teammates/{id}/equipment
GET  /api/teammates/{id}/inventory

POST /api/teammates/{id}/ap
POST /api/teammates/{id}/sp
POST /api/teammates/{id}/skills
POST /api/teammates/{id}/equipment/equip
POST /api/teammates/{id}/equipment/unequip
POST /api/teammates/{id}/equipment/replace

POST /api/trades
POST /api/trades/{tradeId}/offer
POST /api/trades/{tradeId}/confirm
POST /api/trades/{tradeId}/cancel
```

状态变化通过 WebSocket 推送，不允许前端高频轮询完整背包。

## 6. 非功能需求

### NFR-1 服务端权威

- 客户端和外部工具提交的任何操作都不能直接成为最终状态。
- 服务端必须重新校验目标、权限、物品、等级、职业和当前状态。

### NFR-2 一致性

- 背包和装备操作必须具备原子性。
- 同一角色同一时间只能执行一个物品变更事务。
- 交易失败时双方物品和金币必须恢复到交易前状态。

### NFR-3 性能

- 远处或未观察地图上的队友降低 AI 更新频率。
- 战斗、寻路和交易使用有界任务队列。
- 单个 AI 异常不得阻塞共享 ticker 或其他队友。

### NFR-4 可观测性

- 记录队友状态转换、目标、移动目标、技能、补给、死亡和复活。
- 记录外部工具操作者、目标、请求参数和结果。
- 支持按角色查询最近日志。

### NFR-5 安全

- 管理 API 必须认证。
- 高风险操作必须确认。
- 默认只允许控制已绑定的 AI 队友。
- 不允许外部工具生成不存在或非法的物品。
- 所有修改必须审计。

## 7. MVP 验收标准

### AC-1 跟随

- 队长跨越至少 3 张连续地图后，队友仍能到达队长地图。
- 队友死亡后能够复活，并通过寻路重新到达队长地图。

### AC-2 战斗与补给

- 队友在同一地图连续刷怪 10 分钟不需要人工干预。
- 队友能够自动吃药、使用主要技能并拾取符合条件的掉落。
- 背包满或药品耗尽时能够停止危险行为并上报状态。

### AC-3 月妙

- 队友能够完成一次完整月妙流程。
- 流程中不永久卡死，不丢队，不重复无限重试。

### AC-4 Boss

- 至少完成一个站桩型 Boss 和一个机制型 Boss 的基础流程。
- 队友能够死亡复活、重新进入和恢复战斗。

### AC-5 外部工具

- 能够读取队友完整基础状态、技能、装备和背包。
- 能够安全修改 AP、SP、技能和装备。
- 能够与队友完成一次双向交易。
- 修改后游戏内角色属性和装备显示正确。

## 8. 当前 SoloMapling 实现盘点

状态定义：

- 已满足：现有实现已经覆盖 MVP 主要行为。
- 部分满足：有可复用基础，但缺少 MVP 必需部分。
- 未满足：当前没有可用实现。

### 8.1 已满足

| 能力 | 当前实现 |
|---|---|
| 服务端真实 Character | AI 使用服务端 `Character` 对象，并通过共享 `BotClient` 运行 |
| 冒险岛 Party | `BotPartyCommands` 支持创建、加入、邀请和接受邀请 |
| 同地图和跨地图跟随 | `FollowerBot`、`GCMovement`、`GCFollow` 已有完整移动基础 |
| 普通寻路 | 已支持平台、绳索、梯子、瞬移技能和跨地图路线 |
| 普通怪物攻击 | `TrainingBot`、`GrindBrain`、`BotAttackDriver` 已能寻找目标并攻击 |
| 单体、群体和终极技能 | `BotAttackConfig`、`BotAttackProfile` 已按职业和武器选择技能 |
| 自动拾取 | `GrindLoot` 已支持脚边拾取和移动扫荡拾取 |
| 怪物掉落 | `BotAttackEffects` 已为机器人击杀生成正常所有权掉落 |
| 队友交易底层 | `BotTradeSM`、`BotTradeCommands` 已支持交易物品、金币和确认 |
| 一个机制副本 | `OPQBot` 和 `OPQOrchestrator` 已实现完整的 OPQ 阶段协作 |
| Boss 大尺寸攻击判定 | `BotAttackDriver` 已为 Boss 多部位提供扩展命中范围 |
| GM 调试命令 | `!bot`、`!move`、`!tradebot` 等已可手动创建、转换和测试机器人 |

### 8.2 部分满足

| 能力 | 当前缺口 |
|---|---|
| 跟随和战斗一体化 | `FollowerBot` 主要负责移动，`TrainingBot` 主要负责刷怪，尚未形成统一 `CompanionBot` |
| 队友战斗属性 | 机器人伤害主要按等级、职业和配置生成，尚未完全读取 AP、SP、技能和装备真实属性 |
| Buff | 已能播放 Buff 效果，并给真人队友应用部分真实 Buff，但机器人自身多数 Buff 仍偏视觉表现 |
| 掉落管理 | 能自动拾取，但尚无完整白名单、黑名单、背包满处理和转交队长策略 |
| 租用任务 | OPQ 已满足，月妙、跳箱和其他副本尚未接入队友 AI |
| Boss | 有目标攻击和基础命中，但没有 Boss 阶段、危险技能、走位和重进档案 |
| 死亡和复活 | 当前接触伤害和掉落伤害是视觉效果，机器人没有真实 HP 和死亡流程 |
| 交易 | 适合商店/机器人物品交换，但外部工具驱动的稳定双向交易尚未封装成服务 API |
| 持久化 | 机器人在线状态不走完整玩家自动保存路径，当前更适合临时机器人和环境 Population |

### 8.3 未满足

| 能力 | 当前状态 |
|---|---|
| 自动吃 HP/MP 药 | 当前没有队友自动补给系统 |
| 队友真实死亡与复活 | 当前机器人被明确设计为不会因接触伤害死亡 |
| 月妙 AI | 服务端脚本存在，但没有队友状态机 |
| 跳箱通用 AI | 只有录制移动和部分测试能力，没有通用任务执行器 |
| Boss 档案系统 | 当前没有可配置的 Boss 阶段和机制行为 |
| 外部管理 RPC | 当前没有 HTTP、WebSocket 或等价管理 API |
| 外部管理 UI | 不存在 |
| AP/SP/技能远程修改工具 | 服务端有角色 API 基础，但没有外部管理接口 |
| 背包与装备管理 UI | 不存在 |
| 外部交易工作流 | 不存在完整的事务、权限和审计链路 |

## 9. 结论

当前 SoloMapling 已经具备以下强基础：

```text
组队
跨地图跟随
地图寻路
普通怪物战斗
技能选择
自动拾取
物品掉落
交易底层
一个完整机制副本
```

本阶段真正缺少的是：

```text
真实 HP/MP/死亡/复活
自动吃药
跟随和战斗统一状态机
装备与技能影响真实战斗
月妙任务 AI
通用 Boss 策略
队友持久化
外部管理 API
外部管理 UI
服务端事务化背包、装备和交易接口
```

建议实现顺序：

1. 建立统一 `CompanionBot` 状态机。
2. 接通真实 HP、MP、吃药、死亡和复活。
3. 让装备、AP、SP 和技能参与真实属性与伤害计算。
4. 实现外部管理 API 的只读接口。
5. 实现 AP、SP、技能、装备和交易的写接口。
6. 完成月妙任务。
7. 建立 Boss Profile 并完成两个代表性 Boss。
8. 最后补充持久化、监控、安全和管理 UI。
